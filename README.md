# Pump Detector Bot

Бот мониторит **все USDT-перпетуалы** Binance Futures и Bybit (linear) и присылает алерт в
Telegram-канал, когда обнаружен резкий аномальный рост цены (памп) — повод рассмотреть шорт.

**Бот не торгует.** Ордеров, ключей, вебсокетов и БД нет — только публичные REST-эндпоинты.

## Установка

```bash
cd pumpbot
python -m pip install -r requirements.txt      # единственная зависимость — aiohttp
```

Требуется Python 3.11+ (проверено на 3.12).

## Настройка

В `config.json` заменить плейсхолдеры в секции `telegram`:

| поле | что вписать |
|---|---|
| `bot_token` | токен бота от @BotFather вместо `ВСТАВЬ_ТОКЕН_БОТА` |
| `chat_id` | id канала (например `-1001234567890`) вместо `ВСТАВЬ_CHAT_ID_КАНАЛА` |

Бот должен быть админом канала (право отправлять сообщения).

## Запуск

```bash
python pump_bot.py                     # конфиг рядом со скриптом
python pump_bot.py --config my.json    # свой конфиг
```

Остановка — `Ctrl+C` (graceful shutdown). Логи идут в stdout и в `pump_bot.log`.

Первые **120 минут** после старта (`universe.min_history_minutes`) бот молчит: набирает историю
15-минутных доходностей и объёмов, без неё z-score считать не на чем. В логе это видно по
строке `старт: накопление истории 120 мин ...` и отсутствию алертов.

Если в консоли Windows русский текст выглядит как «РїРѕСЂРѕРі», выставьте
`set PYTHONIOENCODING=utf-8` — файл `pump_bot.log` всегда в UTF-8.

### Windows: автозапуск

```powershell
schtasks /create /tn "PumpBot" /tr "python C:\Users\<user>\pumpbot\pump_bot.py" /sc onstart /rl highest
```

## Как работает детекция

1. **Опрос** каждые 10 сек: Binance `ticker/24hr` и Bybit `v5/market/tickers` — параллельно, одним
   запросом на биржу. Funding по Binance (`premiumIndex`) — раз в 60 сек, по Bybit берётся из тикеров.
2. **Состояние** по каждому `EXCHANGE:SYMBOL`: тики `(время, цена, кумулятивный 24h-объём)`,
   история 15-минутных доходностей и 15-минутных объёмов. Интервальный объём восстанавливается
   как дельта кумулятивного 24h-объёма; отрицательная дельта (скользящее окно) — замер пропускается.
3. **Допуск** символа: 24h-объём ≥ $10M, символ не в чёрном списке, с первого появления прошло ≥ 120 мин,
   в истории ≥ 30 наблюдений.
4. **Статистика**: `mu`/`sigma` по истории доходностей (текущее наблюдение в статистику не входит —
   иначе сам памп поднимает среднее и глушит свой же z-score), `sigma` не ниже 0.25 п.п.,
   `vol_baseline` — средний 15-минутный объём.
5. **Триггеры** (алерт, если сработал любой):
   - **MAIN** — `z ≥ 4` **и** `move_15m ≥ 6%` **и** `vol_15m ≥ 4x` baseline;
   - **FAST** — `move_5m ≥ 7%` **и** `vol_5m ≥ 5x` от baseline, пересчитанного на 5-минутное окно.
6. **BTC-фильтр**: если BTC вырос ≥ 2% за 15 мин, все пороги умножаются на 1.3 — на общем росте
   рынка альты тянутся за BTC, и обычные пороги дают мусор. BTC исключён из алертов, но статистика
   по нему ведётся.
7. **Анти-спам**: cooldown 60 мин на символ (общий для двух бирж), дедуп между биржами (одна монета —
   один алерт, в заголовке обе биржи, цифры берутся с биржи с бóльшим z), лимит 40 алертов
   на скользящие 24 часа.

## Формат алерта

```
🔴 PUMP: XYZ/USDT [BINANCE + BYBIT]
⚡ FAST +8.2%/5м — вертикаль          ← только при FAST-триггере
📈 +11.2% / 15м  (+8.2% / 5м)
⚡ z-score: 7.4 | Vol: 6.3x avg
💰 Цена: 0.0432 | 24h Vol: $38.2M
💸 Funding: 0.180%
🕐 14:32:07 UTC
📊 График (ссылка: https://www.tradingview.com/chart/?symbol=BINANCE%3AXYZUSDT.P)
```

## Таблица тюнинга

Все параметры — в `config.json`, в коде нет ни одного дублирующего числа.

### `detection`

| параметр | эффект | меньше сигналов | больше сигналов | default |
|---|---|---|---|---|
| `zscore_threshold` | во сколько sigma должен уложиться рост, чтобы считаться аномальным | 5.0–6.0 | 3.0–3.5 | 4.0 |
| `min_abs_move_main_pct` | минимальный рост за 15 мин, %, отсекает «статистически значимую мелочь» | 8.0–10.0 | 4.0–5.0 | 6.0 |
| `volume_mult_main` | во сколько раз 15м-объём должен превысить средний | 6.0 | 2.5–3.0 | 4.0 |
| `fast_move_pct` | рост за 5 мин для FAST-триггера, % | 9.0–10.0 | 5.0–6.0 | 7.0 |
| `volume_mult_fast` | объёмный множитель для FAST | 7.0 | 3.0 | 5.0 |
| `sigma_floor_pct` | нижняя граница sigma, п.п.; защита от взрыва z на «мёртвых» монетах | 0.4–0.5 (жёстче) | 0.15 (мягче) | 0.25 |
| `min_observations` | минимум наблюдений для расчёта статистики | 60–100 | 30 (ниже не рекомендуется) | 30 |
| `window_main_sec` | основное окно, сек | — | — | 900 |
| `window_fast_sec` | окно вертикали, сек | 180 (резче) | 600 (шире) | 300 |
| `ticks_maxlen` / `history_maxlen` | глубина памяти на символ | — | — | 9000 / 8640 |

### `universe`

| параметр | эффект | меньше сигналов | больше сигналов | default |
|---|---|---|---|---|
| `min_24h_volume_usd` | порог ликвидности, ниже — не смотрим | 30–50M | 3–5M | 10M |
| `exclude_symbols` | монеты без алертов | добавить крупные L1 (SOL, BNB, XRP) | оставить только BTC | BTC, ETH |
| `min_history_minutes` | сколько молчать после старта / после листинга | 240 (надёжнее) | 60 (быстрее, шумнее) | 120 |

### `btc_filter`

| параметр | эффект | меньше сигналов | больше сигналов | default |
|---|---|---|---|---|
| `btc_move_15m_pct` | при каком росте BTC включается режим «рынок летит» | 1.5 (включается чаще) | 3.0 (почти никогда) | 2.0 |
| `threshold_multiplier` | во сколько поднимаются все пороги в этом режиме | 1.6–2.0 | 1.1 | 1.3 |

### `alerts`

| параметр | эффект | меньше сигналов | больше сигналов | default |
|---|---|---|---|---|
| `cooldown_min` | пауза по одному символу, мин | 120–180 | 15–30 | 60 |
| `max_per_day` | лимит алертов на скользящие 24ч | 15–20 | 100 | 40 |
| `day_window_sec` | окно этого лимита, сек | — | — | 86400 |

### `network`

| параметр | эффект | значение |
|---|---|---|
| `poll_interval_sec` | частота опроса; ниже 5 сек не нужно — 24h-объём на биржах обновляется не чаще | 10 |
| `request_timeout_sec` | таймаут запроса | 15 |
| `backoff_start_sec` / `backoff_max_sec` | экспоненциальный backoff при HTTP 429/418 | 30 / 900 |
| `funding_refresh_sec` | как часто обновлять funding по Binance | 60 |
| `error_sleep_sec` | пауза после необработанной ошибки в итерации | 5 |

## Тесты

Оффлайн, без сети: время в боте берётся из подменяемой функции `pump_bot.now()`, поэтому 4 часа
рынка прогоняются за секунду.

```bash
python -m unittest discover -s tests -v
```

Покрытые кейсы:

1. 4 часа спокойного рынка (шум ±0.08% на тик) → сигналов нет;
2. памп +9%/15м с объёмом 6x → сигнал есть, z > 4, обе биржи склеены в один алерт;
3. памп +6.5%: при `btc_mult` 1.3 отсечён, при 1.0 — проходит;
4. второй памп той же монеты через 5 минут подавлен cooldown'ом (контроль: при `cooldown_min = 0`
   он проходит — значит подавил именно cooldown);
5. отрицательная дельта объёма → интервальный объём `None`, детектор не падает и сигнал не выдаёт.

## Надёжность

- сетевые ошибки и таймауты → WARNING, цикл продолжается; HTTP 429/418 → экспоненциальный backoff
  с 30 сек по каждому эндпоинту отдельно;
- одна `aiohttp.ClientSession` на весь lifetime;
- любое необработанное исключение внутри итерации логируется (ERROR + traceback), цикл возобновляется
  через 5 сек;
- ошибка отправки в Telegram → ERROR, бот работает дальше;
- длительность итерации учитывается: `sleep = max(1, poll_interval - elapsed)`;
- всё состояние — в памяти, при рестарте история набирается заново (см. `min_history_minutes`).
